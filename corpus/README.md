# The Corpus

`documents.jsonl` and `chunks.jsonl` are generated, committed artifacts —
regenerated with `python scripts/generate_corpus.py`, never hand-edited.
`counts.md` is regenerated the same way and a test fails if it drifts from
what the inventory and generator actually produce.

## Provenance

This build's Corpus was generated by the build-time assistant, executing
the prompt templates in `prompts/corpus/` directly and committing the
result — the build-time assistant may generate the Corpus itself, though
never an output being measured or ground truth that has not been verified
by hand. Every document's `generated_by` field records this as `local`.

**Different model family than the answerer.** The runtime answerer, once
a fallback chain is chosen, is a free-tier provider distinct from whatever
generated the Corpus. The two are a different model family by
construction — the generator does not additionally have to call a second
live model to prove it.

**Independent regeneration.** `python scripts/generate_corpus.py --live`
exists for a reviewer who wants to regenerate the Corpus themselves
against a real OpenAI-compatible provider of their choosing, following
the exact templates in `prompts/corpus/`, configured with
`NIVARA_CORPUS_MODEL_PROVIDER`, `NIVARA_CORPUS_MODEL_NAME`,
`NIVARA_CORPUS_MODEL_BASE_URL` and `NIVARA_CORPUS_MODEL_API_KEY`. This is
not wired into any build or CI path — regeneration is a deliberate,
quota-spending choice a reviewer makes, not something that happens
automatically. A `--live` run stamps each document's `generated_by` as
`live:<provider>/<model>` so the two provenances are never confused.

## What is generated, and what is not

- **80 `Document`s**, one per Scenario in `scenarios/inventory.jsonl` —
  50 `answerable` documents for ordinary Scenarios, and 30
  `retrieve_but_refuse` documents for sensitive ones. Nivara Desk has no
  refund, payout or KYC capability of its own, so a sensitive Scenario
  never gets an `answerable` document; the retrieve-but-refuse documents
  are genuinely relevant to their Scenario's topic — verification
  requirements, case-by-case review, how to contact support — without
  resolving any specific case, so the Gate is tested against strong
  retrieval rather than an empty result.
- **240 `Chunk`s**, split from each Document's body on paragraph
  boundaries by `chunk_body` in `src/nivara_ai/corpus/generate.py`. This
  chunker is provisional — chunking strategy and size are decided by the
  retrieval ablation (decision 27), not here; when the
  ablation picks a different strategy, `chunk_body` is what changes, not
  the Documents.
- **A contextual prefix per chunk** (decision 22a), stored in
  `contextual_prefix` alongside the raw `text` and the combined
  `prefixed_text`, so the ablation can toggle contextual chunking on or
  off without regenerating anything.
- **Nothing from the fifty seeded real Tickets.** This generator reads
  only `scenarios/inventory.jsonl`; it has no code path that touches
  Ticket data at all, so the Real-phrasing slice cannot leak into the
  Corpus by construction, not by filtering.
